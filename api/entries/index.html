    A single sequence entry in a PEFF file.

    Frozen and compared by value (==), but not hashable: custom_values and extra are dicts, so hash(entry) raises :class:TypeError. Key sets or dicts by (entry.prefix, entry.db_unique_id) instead.

    id holds the \ID= key (spec §3.3.4); the name shadows the builtin but is kept for API stability.

    Render the sequence with its modifications as a ProForma 2.0 string.

    mods="psimod" writes \ModResPsi sites (S[MOD:00046]) and "unimod" writes \ModResUnimod sites (S[UNIMOD:21]). \ModRes sites are included when their accession is from the same vocabulary; others are left out. An empty accession is written by name ([M:name] / [U:name]). Every listed site is modified at once. Unknown positions (?) become a ProForma unknown-position prefix ([MOD:00046]^2?SEQ); they are dropped when a * variant truncates the sequence, since they may lie in the removed part. A site listed in both \ModResPsi/\ModResUnimod and \ModRes is written once, even in different case, spacing or zero-padding (MOD:00046, mod:00046, MOD:46, MOD: 00046). The CV prefix is written in upper case, and numeric accessions in canonical form: PSI-MOD zero-padded to 5 digits (MOD:00046), Unimod unpadded (UNIMOD:21). PEFF cannot tell a terminal modification from one on the terminal residue, so all are written on the residue.

    Real files contain entries whose sites lie past the end of the sequence (12 of the 20,431 entries of the neXtProt human PEFF). Converting a whole file, pass errors="skip" to get None for those entries instead of an exception::

    forms = [p for e in entries if (p := e.to_proforma(errors="skip")) is not None]

    Apply variants to the sequence and return the resulting :class:VariantForm.

    A PEFF entry's sequence line holds the reference sequence; \VariantSimple (spec §3.3.8) and \VariantComplex (§3.3.9) describe sequences it does not contain. This builds one of them: the form's entry is an ordinary :class:SequenceEntry, so to_proforma, to_record and write_peff work on it unchanged.

    Every other annotation is carried onto the new coordinates through VariantForm.position_map:

    • A modification site the variant removed is dropped, as is one on a residue a VariantSimple substituted (§3.3.10: a modified variant needs its own entry). A ? position is kept as written. A modification left with no site is dropped.
    • Processed, un-applied VariantComplex and Proteoform ranges are remapped by both endpoints, and dropped rather than clipped when either endpoint was removed.
    • DisulfideBond and Proteoform references are annotation ids, not positions (§3.4.2), so they are copied; the annotation holding them is dropped when a reference no longer resolves, including a reference to a variant this form applied. A reference that was already dangling is left alone.
    • length is recomputed when the entry had one; the applied variants are removed from variant_simple / variant_complex by equality, so passing a rebuilt variant rather than the entry's own instance removes the right one.

    Each drop emits a :class:PeffWarning; nothing is silent.

    def apply_variants(
    self,
    variants: Iterable["VariantSimple | VariantComplex"] = (),
    *,
    errors: Literal["raise", "skip"] = "raise",
) -> "VariantForm | None":
    r"""Apply *variants* to the sequence and return the resulting :class:`VariantForm`.

    A PEFF entry's sequence line holds the reference sequence; ``\VariantSimple``
    (spec §3.3.8) and ``\VariantComplex`` (§3.3.9) describe sequences it does not
    contain. This builds one of them: the form's ``entry`` is an ordinary
    :class:`SequenceEntry`, so ``to_proforma``, ``to_record`` and ``write_peff`` work
    on it unchanged.

    Every other annotation is carried onto the new coordinates through
    ``VariantForm.position_map``:

    - A modification site the variant removed is dropped, as is one on a residue a
      ``VariantSimple`` substituted (§3.3.10: a modified variant needs its own entry).
      A ``?`` position is kept as written. A modification left with no site is dropped.
    - ``Processed``, un-applied ``VariantComplex`` and ``Proteoform`` ranges are
      remapped by both endpoints, and dropped rather than clipped when either endpoint
      was removed.
    - ``DisulfideBond`` and ``Proteoform`` references are annotation ids, not positions
      (§3.4.2), so they are copied; the annotation holding them is dropped when a
      reference no longer resolves, including a reference to a variant this form
      applied. A reference that was already dangling is left alone.
    - ``length`` is recomputed when the entry had one; the applied variants are
      removed from ``variant_simple`` / ``variant_complex`` by equality, so passing a
      rebuilt variant rather than the entry's own instance removes the right one.

    Each drop emits a :class:`PeffWarning`; nothing is silent.

    Args:
        variants: The variants to apply, usually a subset of ``self.variant_simple``
            and ``self.variant_complex``. Empty gives the reference form.
        errors: ``"raise"`` (default) raises :class:`PeffError`; ``"skip"`` returns
            ``None`` instead.

    Returns:
        The :class:`VariantForm`, or ``None`` with ``errors="skip"``.

    Raises:
        PeffError: Unknown ``errors`` (always). With ``errors="raise"`` also a position
            that is not a number, a position outside the sequence, a ``VariantSimple``
            whose new residue is not a single letter or ``*``, a ``VariantComplex``
            whose replacement is neither residue letters nor empty (§3.3.9), a variant
            downstream of a ``*`` stop, which ends the protein (§3.3.8) so the later
            positions do not exist in that form, or two variants that change the same
            position: the spec does not define how overlapping variants combine, so one
            per form.

    Example:
        >>> from pefftacular import SequenceEntry, VariantComplex, VariantSimple
        >>> entry = SequenceEntry(prefix="sp", db_unique_id="P1", sequence="MSTKW",
        ...                       variant_simple=(VariantSimple(2, "C"),),
        ...                       variant_complex=(VariantComplex(4, 5, ""),))
        >>> entry.apply_variants(entry.variant_simple).sequence
        'MCTKW'
        >>> entry.apply_variants(entry.variant_complex).position_map
        (None, 1, 2, 3, None, None)
        >>> tuple(form.sequence for form in entry.variant_forms())
        ('MSTKW', 'MCTKW', 'MST')
    """
    from pefftacular._variants import entry_apply_variants

    return entry_apply_variants(self, variants, errors=errors)
